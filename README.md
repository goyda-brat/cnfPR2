# depgraph

Инструмент визуализации графа зависимостей для пакетов Rust (Cargo).
Практическая работа №2, вариант 24, этапы 1 и 2.

Данные о зависимостях программа скачивает из индекса реестра
(например, `https://index.crates.io`) и разбирает сама. Менеджеры пакетов и
сторонние библиотеки не используются, только стандартная библиотека Python.

## Файлы

| Файл | Описание |
|------|----------|
| `src/stage1.py` | Этап 1: чтение INI-конфигурации, проверка параметров, вывод «ключ = значение» |
| `src/stage2.py` | Этап 2: то же чтение конфигурации и вывод прямых зависимостей пакета |
| `tests/test_stage1.py`, `tests/test_stage2.py` | Тесты |
| `config.ini` | Пример конфигурации для реального репозитория |
| `examples/` | Пример тестового репозитория и конфигурации для него |
| `Makefile` | Команды `stage1`, `stage2`, `test` |

Каждый этап в одном файле и запускается отдельно.

## Настройки (INI-файл, секция `[depgraph]`)

| Параметр | Обязательный | Описание |
|----------|--------------|----------|
| `package_name` | да | Имя пакета. Обычный режим: буквы, цифры, `-`, `_`, первая буква. Тестовый режим: только большие латинские буквы |
| `repository_url` | да | URL репозитория (`http://` или `https://`). В тестовом режиме: путь к файлу тестового репозитория |
| `test_mode` | да | Режим работы с тестовым репозиторием: `true` или `false` |
| `filter_substring` | нет | Подстрока для фильтрации пакетов (без пробелов). Фильтрация относится к этапу 3 и пока не применяется |

```ini
[depgraph]
package_name = serde
repository_url = https://index.crates.io
test_mode = false
filter_substring = proc
```

## Запуск и тесты

```
make stage1                                   # config.ini
make stage2                                   # config.ini
make stage2 CONFIG=examples/test_config.ini   # тестовый репозиторий
make test                                     # все тесты
```

Без make: `python3 src/stage1.py -c config.ini`,
`python3 src/stage2.py -c config.ini`,
`PYTHONPATH=src python3 -m unittest discover -s tests -v`.

Коды завершения: `0` успех, `1` ошибка получения данных, `2` ошибка
конфигурации. Сообщения об ошибках выводятся в stderr.

## Описание функций

### Этап 1 (`src/stage1.py`)

| Функция | Описание |
|---------|----------|
| `read_config(path)` | Читает INI-файл, возвращает секцию `[depgraph]`. Ошибки: файла нет, неверный формат, нет секции |
| `check_name(name, test_mode)` | Проверяет имя пакета. В тестовом режиме только буквы `A-Z`, иначе допустимое имя Cargo |
| `check_repository(value, test_mode)` | Тестовый режим: файл должен существовать. Обычный режим: адрес должен начинаться с `http://` или `https://` |
| `check_config(section)` | Проверяет все параметры (заданы, `test_mode` равен `true`/`false`, имя и репозиторий верны, в фильтре нет пробелов). Возвращает словарь параметров |
| `print_config(config)` | Печатает параметры в формате `ключ = значение` |
| `main(argv)` | Точка входа. Ошибка конфигурации: сообщение и код `2` |

Все ошибки выбрасываются как `ValueError` с понятным текстом.

### Этап 2 (`src/stage2.py`)

Функции `read_config`, `check_name`, `check_repository`, `check_config`
такие же, как на этапе 1. Вывод параметров на этапе 2 не нужен.

| Функция | Описание |
|---------|----------|
| `index_path(name)` | Путь файла пакета в индексе: `1/a`, `2/ab`, `3/a/abc`, для длинных имён `se/rd/serde` |
| `download(url)` | Скачивает текст по URL. Ошибки: пакет не найден (404), другая ошибка HTTP, сеть недоступна |
| `find_dependencies(text)` | Разбирает индекс (одна строка JSON на версию). Берёт последнюю не отозванную версию и её обычные не опциональные зависимости. Возвращает версию и отсортированный список имён |
| `read_test_repo(path)` | Читает файл тестового репозитория (строки `A: B C`) в словарь «пакет: список зависимостей» |
| `get_dependencies(config)` | Выбирает источник по `test_mode`: тестовый файл или индекс Cargo. Возвращает версию и список зависимостей |
| `print_dependencies(name, version, names)` | Печатает прямые зависимости на экран |
| `main(argv)` | Точка входа. Ошибка конфигурации: код `2`, ошибка данных: код `1` |

Не учитываются зависимости для разработки (`dev`), для сборки (`build`) и
опциональные. Это поведение по умолчанию `cargo tree`.

## Примеры

```
$ make stage1 CONFIG=examples/test_config.ini
package_name = A
repository_url = examples/test_repo.txt
test_mode = true
filter_substring = F

$ make stage2 CONFIG=examples/test_config.ini
Прямые зависимости пакета A:
  B
  C
```

Для реального пакета укажите в `config.ini` `test_mode = false` и имя пакета,
затем `make stage2`. В заголовке будет версия: `Прямые зависимости пакета
имя 1.2.3:`.

Ошибка конфигурации:

```
$ python3 src/stage1.py -c bad.ini
Ошибка: репозиторий должен быть http(s) URL: ftp://x
```
